# Brainstorming

Turn an uncertain idea into a decision the user can evaluate.

1. Restate the intended outcome, audience, and known constraints.
2. Inspect relevant repository context before assuming its architecture.
3. Identify the smallest unanswered questions that materially change the solution.
4. Offer two or three meaningfully different approaches, including their costs,
   risks, reversibility, and operational consequences.
5. Recommend one approach and explain the deciding evidence.
6. Define a thin first version, explicit non-goals, and success criteria.
7. Stop at an implementation-ready brief unless the user also requested implementation.

Challenge feature requests that add ceremony without user value. Distinguish
facts, assumptions, and open questions. Prefer experiments when uncertainty can
be resolved cheaply instead of debated abstractly.
